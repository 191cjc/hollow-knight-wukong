# Research: Boss hurt and stagger candidates

- Query: Which named bosses have evidence of an existing interruption state that Flame Storm could enter after every actual damaging hit, and which apparent stun states must be excluded?
- Scope: mixed; project integration read plus pinned public mod source. No game assets were downloaded, no implementation was changed, and no game-client FSM was inspected for this report.
- Date: 2026-10-27

## Findings

### Conclusion and evidence standard

Boss-specific interruption is technically plausible, but this research establishes **candidates, not a verified support list**. No boss below is approved for runtime support solely from these sources. Boss stagger is a different contract from an ordinary enemy's repeatable hurt reaction. A `Stun` name is insufficient: entry setup, suspended phases, additional attack FSMs, exit behavior, and repeated entry must be checked on the pinned client.

The strongest public original-state clues identify Grimm, Nightmare King Grimm, Pure Vessel, Broken Vessel, and Hornet. The first four are exact state references in EnemyRandomizer; Hornet has an exact original-state reference in ModCommon's resource extraction plus an illustrative C# rewrite. Lost Kin and Hornet Sentinel need independent verification; sharing appearance, FSM name, or a third-party base class does not establish matching native state contracts.

Evidence levels used here:

- **Original-state clue**: third-party source looks up or modifies a named state on the original game FSM. This establishes that mod author's expected state name, not compatibility with client 1.5.78.11833.
- **Rewrite clue**: third-party code implements its own equivalent behavior. This helps locate cleanup obligations but does not prove native state actions or exact native transition names.
- **Unverified**: no suitable exact original-state clue was found in the inspected material. Runtime behavior should skip these targets until independently verified; this does not mean the enemy has no hurt/stagger state.

### Why entry and cleanup must be checked together

- The current skill targets resolved responders through `SkillTargetPolicy`, then calls native spell damage with ownership checks (`src/WukongKnight/FlameStorm.cs:88`–95; `NativeV77.cs:181`–190). The proposed extra interruption belongs only to an **actual surviving target's accepted HP loss**, never an overlap, rejected hit, death transition, or phase/invulnerability bypass. This report does not duplicate the separate native-IL investigation.
- Boss body control is not the whole attack. EnemyRandomizer explicitly locates separate `Spawn Balloon` (Broken Vessel/Lost Kin), `Attack Commands` and `Teleport` (Absolute Radiance). GodSeekerPlus's AbsRad rewind explicitly sets `Attack Commands` to `Idle` and disables an ascend beam separately from changing the main FSM ([G/InfiniteRadianceClimbing:119](https://github.com/Clazex/HollowKnight.GodSeekerPlus/blob/0cd8bb25bd324e30a7dc2fae7fcfef59391651d4/GodSeekerPlus/Modules/BossChallenge/InfiniteRadianceClimbing.cs#L119)). A frozen/reeling body does not establish removal of independently spawned hazards.
- Restarting a full stagger entry may relaunch the enemy or replay sounds/VFX. Restarting only an animation may omit attack cleanup or be canceled by the next damage event. The user chose every accepted damaging hit to restart hurt, so per-boss state entry and exit must explicitly satisfy that choice; normal stagger's "next hit wakes the boss" behavior cannot be accepted unchanged.
- No numeric stagger hit counts, native phase thresholds or universal stun event name are asserted here. The public mod excerpt does not establish them for the pinned client.

### Minimum evidence to promote a boss from candidate to supported

1. Capture the exact pinned-client scene, object path, FSM name, normal event/entry route, full entry/air/land/recovery states and native death/phase gates. Keep original variants and Godhome variants separate until their signatures are established.
2. Inspect all relevant state actions and transition sources: colliders, gravity/velocity, transient invulnerability, spawned hazards, additional FSMs, stun counters and phase variables. Identify safe cleanup supplied by the **native** route rather than copying randomizer changes.
3. Verify every accepted Flame Storm hit restarts from an allowed active attack and during the hurt state itself, including a final surviving hit. Preserve normal damage rejection, deaths and phase transitions. Re-hit behavior must not wake the boss, leave it suspended, advance a phase or bypass missing prerequisites.
4. Verify natural recovery after the final hit on ground and in air; no stranded `LAND` dependency, residual damaging melee hitbox, frozen death or corrupt subsequent attack. If compatible entry/recovery cannot be established, skip interruption while keeping normal damage.

## Caveats / Not Found

- No game installation/scene asset FSM dump or successful in-client interruption was inspected. The client compatibility baseline is Hollow Knight 1.5.78.11833 / Modding API v77; public source versions do not establish that baseline's serialized FSM actions.
- The current shortlist is **five named boss candidates, zero verified supported bosses**. It is not an exhaustive list of bosses with a stagger mechanic. Only Absolute Radiance's phase-transition `Stun1` has sufficient evidence here for a concrete incompatible-route exclusion; unknown bosses should be labeled unverified rather than nonexistent-state enemies.
- Wiki requests to `hollowknight.wiki` (`Stagger`, `Grimm`, `Pure_Vessel`, `False_Knight`, `Radiance`) all returned HTTP 403; no wiki-derived threshold or boss list is used. A GodSeekerPlus God Tamer collider file timed out and is not used as evidence. DebugMod candidate files yielded no relevant hurt/stagger references and are not used.
- The word "hurt" remains a product-scope decision for bosses: a full boss stagger sequence can be longer, airborne, hidden or vulnerable only in certain intervals. A short repeated hurt lock cannot be promised merely because a boss has a long stagger sequence. Preserve the user's skip-incompatible requirement.
