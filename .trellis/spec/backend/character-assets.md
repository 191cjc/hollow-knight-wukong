# Character Asset Pipeline Contract

## 1. Scope / Trigger

Use this contract when changing the offline character bake, generated JSON, Unity sprite loading, validation or packaging. These layers share one schema; a successful PNG decode alone does not verify character composition or game behavior.

Source-backed implementation: `tools/legacy_dragonbones.py`, `tools/bake_character.py`, `tools/validate_character.py`, `src/WukongKnight/CharacterAssets.cs` and `tools/package.py`.

## 2. Signatures

```bash
python3 tools/bootstrap.py
.tools/python/bin/python tools/bake_character.py
.tools/python/bin/python tools/bake_character.py --force --output <directory>
.tools/python/bin/python tools/bake_character.py --validate-only
.tools/python/bin/python tools/validate_character.py --update-development-manifest
bash scripts/build.sh
```

The Python API is `validate_character(directory=CHARACTER, source_directory=None) -> ValidatedCharacter`, with `.manifest`, `.files` and `.frame_count`. Packaging uses its validated file list rather than recursively archiving an arbitrary working directory.

## 3. Contracts

- Checked-in profile: `data/character/wukong-staff.json`. Generated files: `assets/processed/wukong/character.json` and referenced atlas pages. Packaged location: `WukongKnight/character/`; runtime resolves it beside its own DLL.
- Preserve both archived originals and the unscaled baked character. `tools/resize_character.py` / `scripts/resize-character.bat` write offline size variants into separate folders; `data/character/active-variant.json` selects the packaged variant. Keep baseline nominal body calibration, scale frame/pivot/feet pixels, and retain animation/combat settings. Reject overlapping source/output, cumulative rescaling and replacement of a different existing variant. See `docs/ASSET_VARIANTS.md`.
- `scripts/prepare-all-assets.bat` / `tools/prepare_all_assets.py` prepare the all-image mirror plus the selected staff bake. Keep earlier 13-clip and 22-clip bakes intact. The complete profile has 21 staff clips plus `flameDash`; the active Fire Demon profile adds five clips below. Source-backed Flame Dash uses only the verified single local DragonBones 3.0 effect2 bone/slot, not generic 3.0 support. Runtime requires the 13 baseline clips, `flameDash` and five Fire Demon clips; other prepared skill clips do not imply playable mechanics.
- JSON schema_version is 1. Required identity: character_id `2001`, appearance `default_staff`, frame_rate 30. Generated bytes omit timestamps so the same inputs/dependencies produce identical output.
- The 0.4 Fire Demon profile adds five separate runtime clips: fireDemonAir (38), fireDemonAirEffect (31), fireDemonDive (1), fireDemonLand (21), fireDemonImpact (20), for 27 clips total including Flame Dash. Do not composite the world air effect into the body view; it must remain fixed after spawn. The bounded skill5 reader accepts only the observed parentless local DragonBones 3.0 armatures. The playable 0.4.3 skill uses the existing untouched effect5 clip with moving character flashes and genuine blink gaps; require it at runtime. Keep the normalized/held legacy compatibility clips and original bakes intact. Real-source tests compare baked effect5 pixels to direct sampling and verify travel/empty frames. The active folder is selected by `active-variant.json`; preserve earlier original/variant folders.
- Manifest includes source hashes, generator version/Pillow version/filler rule, common canvas dimensions, root_x/root_y, nominal_body_height, atlas path/dimensions/SHA256, clip durations/loop/frame rectangles and combat settings.
- All rectangles and root coordinates are PNG top-left/y-down. Unity converts rectangle Y using `atlas.height - y - height` and pivot Y using `1 - root_y / canvas_height` independently. Sprite pixels-per-unit is 100; view scale maps nominal body height to the existing hero collider.
- `CharacterAssets.ArtworkScale` reads offline `asset_transform.scale` (default 1 for an unscaled bake). Use it only to register centered effect pixels against a fixed world anchor. It must not multiply renderer appearance scale, hero collision or damage-region dimensions; those enlarged pixels already exist in the atlas.
- Every frame uses the same canvas/root. Identical frames can share one rectangle while retaining their individual tick records. Do not independently center or resize attack frames; a longer staff cannot shrink the body.
- Required clips: idle, walk, runNormal, jumpNormal, jumpTwo, jumpDown, jumpAttack, hurtStand, dead, attack1 through attack4.
- Combat has four ordered stages, finite chain grace, buffer_open_tick, positive range_multiplier and half-open integer hit windows. Third stage has two nonoverlapping windows; the other stages have one. These are authored transplant timings, not proof of original AS3 hit semantics.
- Current legacy source has parentless global poses, numeric equipment animation `1`, hidden animation `0`, missing-timeline hiding and disabled tweening. Compose nested armatures and both frame/display pivots; do not add bind poses to global frame transforms.
- Normalize only exact source filler RGBA `(0,0,0,1)` to transparent in generated copies. Preserve other semitransparent edges and source provenance. Historical DragonBones MIT notices belong with substantially translated math/parser logic; artwork has separate provenance.
- Dependencies live under `.tools/`. Pillow and compile references are pinned; game/API/engine DLLs are compiler inputs and must not enter the Mod package. Preview images are review outputs, not runtime files.

## 4. Validation & Error Matrix

| Condition | Required behavior |
| --- | --- |
| Unsupported legacy feature or unresolved display | Bake fails explicitly; do not silently omit body parts or invent modern defaults. |
| Missing clip, invalid tick total, overlapping/out-of-range hit windows | Validation fails before build/package acceptance. |
| Atlas path escapes character directory, missing file, wrong hash/dimensions | Validator rejects it; runtime initialization fails before hiding the native body. |
| Schema version/appearance not supported | Runtime restores/retains native hero and logs a specific initialization failure. |
| Repeated source-tick pose | Shared atlas rectangle is allowed; total duration must remain unchanged. |
| Compile/bake succeeds without client execution | runtime_tested remains false; client acceptance stays pending. |

## 5. Good / Base / Bad Cases

- Base: default profile generates 13 clips and a complete validated runtime file closure.
- Good: two clean regenerations produce identical manifest/atlas bytes; source holds are deduplicated without changing clip duration, root or hit windows.
- Bad: treating an empty equipment animation as bind-pose visibility, adding tweening to the held source frames, packing previews/game DLLs, or declaring real gameplay passed from file validation.

## 6. Tests Required

- Python animation tests cover global affine composition, numeric child animation visibility, missing timelines, two pivot types, negative scales, last-frame repair, death child activation and exact filler cleanup.
- Inspect actual preview/contact sheets for default body/staff, layer order, held keyframe boundaries and common root. Structural tests cannot establish a coherent assembled character.
- Contract/package tests reject changed hashes, escaping/missing files, invalid frame rectangles/totals/windows and accidental dependency inclusion.
- Rebuild with the local pinned environment and inspect the resulting package. Game scale, facing, transparency and lifecycle are client checks.

## 7. Wrong vs Correct

Wrong: choose each frame's opaque bounding-box center as its Unity pivot, then scale every frame to the same visible width.

Correct (the runtime's independent coordinate conversions):

```csharp
var rect = new Rect(x, texture.height - y - height, width, height);
var pivot = new Vector2(rootX / width, 1f - rootY / height);
var sprite = Sprite.Create(texture, rect, pivot, 100f, 0, SpriteMeshType.FullRect);
```

The constant source root and nominal body scale preserve the feet and body while the weapon moves.
